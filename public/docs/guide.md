But underneath that navigation, the documentation should be built around four different ways of learning:

1. Learn

For people who are new.

2. Do

Step-by-step instructions for completing tasks.

3. Solve

Troubleshooting and “I have a problem” content.

4. Reference

Detailed explanations of features, settings, terminology, rules and system behaviour.

That separation is extremely important.

Documentation should be updated alongside product releases.

If you eventually have materially different product versions, documentation versioning can preserve the correct instructions for older releases; systems such as Docusaurus support this explicitly.

But don't version every tiny change. Documentation versioning introduces maintenance complexity and is generally most useful when releases materially change the product.
